## 优化方案后果评估（只读审查，未改代码）

### 两项关键修正
1. **P0-1 比方案描述的更严重**：`static/index.html:407` 与 `:461` 顶层重复 `let allProblems=[]`，属经典 `<script>`（非 module）解析期 SyntaxError → **整段内联脚本完全不执行**。意味着当前前端在真实浏览器里 100% 是死的（导航/数据/弹窗全无），"✅ 完整单页应用"实际是"已写但未运行"。61 个单测全是后端，无前端 JS 测试，验证有盲区。
2. **P0-2 的"环境变量优先"不成立**：`ai.py:43` `config=get_cached_settings()` 只从 SQLite `settings` 表读 key，`config.py` 也无 api_key 的 env 读取。**若直接删 DB 落库而不加 `PHYSICS_OS_API_KEY` 支持，应用将完全无法配置密钥**。P0-2 必须配套新增环境变量读取，不能只删写入。

### 其他后果要点
- P0-3 Origin 校验易过度拦截：必须只限 POST/PUT/DELETE、放行同源、放行无 Origin 的 GET，否则 403 误杀正常请求。
- P1-2 导入有 SQL 注入/DB 损坏风险，须参数化 + 先备份。
- P1-3 自动重试 POST 会导致重复建题，须仅重试 GET 或加幂等键。
- P1-10 改掌握度刻度会破坏现有 1–5 数据语义，建议仅"标注说明"而非改 schema。
- P1-12 启用 WAL 会生成 `-wal/-shm/-journal` 文件，`.gitignore` 当前仅 `*.log`，须补忽略规则。
- P1-13 日志落盘须确保不记录 api_key（ai.py 会读取密钥）。
